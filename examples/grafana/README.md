# Дашборд Grafana

`express-botx.json` — пример дашборда для метрик сервера (`serve` и
`serve --enqueue`). Как включить метрики и что они значат —
[docs/deployment.md](../../docs/deployment.md#метрики-prometheus), раздел «Метрики Prometheus».

## Импорт

Dashboards → New → Import → загрузить `express-botx.json`. Источник данных
выбирается переменной `Data source` вверху дашборда, отдельно при импорте
его указывать не нужно. UID дашборда — `express-botx`; если такой уже есть,
поменяйте его при импорте.

Нужен источник данных Prometheus. Импорт и запросы проверены на Grafana 12.3
и 13.1.

## Переменные

- `Job`, `Namespace`, `Instance` — фильтры по меткам, которые Prometheus
  ставит при сборе. Значения берутся из `express_botx_build_info`. Если метки
  `namespace` нет (сбор не из Kubernetes), фильтр оставьте `All`.
- `Rate window` — окно для `rate()` и квантилей, по умолчанию `5m`. Берите
  его не меньше четырёх интервалов сбора: в коротком окне одна-две точки, и
  панели пустеют. При большом периоде увеличивайте окно: если шаг графика
  больше окна, отсчёты между точками графика не учитываются.

  Встроенный `$__rate_interval` не используется намеренно. Grafana считает его
  от интервала сбора, указанного в источнике данных (Scrape interval, по
  умолчанию 15 с), а не от реального. Если Prometheus собирает раз в минуту, а
  в источнике это не указано, окно выходит слишком коротким. Когда интервал
  сбора в источнике задан верно, `$rate_window` можно заменить на
  `$__rate_interval`.

## Что на дашборде

- **Overview** — число инстансов, версии (`build_info`), запросы в секунду,
  чаты с исходом `delivered` или `queued` и с ошибкой за выбранный период,
  ответы BotX не `2xx`. `queued` (режим `--enqueue`) значит, что сообщение
  попало в очередь, а не что получатель его получил.
- **HTTP server** — запросы по маршрутам и статусам, ответы `4xx`/`5xx`,
  задержка p50/p95/p99 и p95 по маршрутам.
- **Deliveries** — исходы по чатам (`delivered`, `queued`, `failed`),
  неудачные чаты по маршрутам, частичные доставки, редактирование постов.
- **BotX API** — попытки по эндпоинтам и статусам, ответы не `2xx`, задержка
  p95 по эндпоинтам.
- **Membership checks** (свёрнут) — проверки членства для ключей с
  `chats_where_member`: исходы, доля ответов из кеша, запросы в BotX, отказы
  по лимиту.
- **Queue publishing** (свёрнут) — публикации в очередь в режиме `--enqueue`.

Некоторые панели могут быть пустыми, пока не было событий: например, ответов
с ошибкой или правок постов, а доля ответов из кеша — пока не было проверок
членства.

Имена метрик в запросах сверяет с кодом тест
[internal/metrics/dashboard_test.go](../../internal/metrics/dashboard_test.go).
